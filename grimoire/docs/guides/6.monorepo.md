# Monorepo

There's not much special to working with a monorepo - how
you want to organize your documentation and code is up to you.
Grimoire simply provides components and tools to allow you
to scaffold your documentation site to your liking.

However, there are some simple techniques you can use
or draw inspiration from that can help you organize
your documentation better!

## Per-Package Documentation

If you have a main documentation entry point/site
sitting inside a `/doc` subdirectory or such, you
can choose to put all your documentation resources
in there.

But, I personally enjoy having the documentation
"closer" to the code its documenting, filesystem wise.

If you prefer that too, consider (in addition to your
main documentation site), having each package
include a `/${myPackage}/docs` directory.

> Make sure to not accidentally include any
> `docs` exports in your package.
> It's not a crime to include the files (filesize permitting)
> but if you reference variables inside your `/docs` directory
> in a published package, users of your package will probably
> receive an error about not having @lukekaalim/grimoire installed.

Your repository should look like:

  - `docs/main.ts`
  - `packageA/docs/index.ts`
  - `packageB/docs/index.ts`
  - `packageC/docs/index.ts`

Each of your respective "packageX" doc index files
should export a specific createDocs function which accepts
a DocBuilder instance, and use it to set up it's own
little section of the website.

If your App uses plugins (like our example does), make
sure to list "required" plugins in the generic parameters
of the type.

```ts
// packageX/docs/index.ts

export const createDocsPackageX = (doc: DocBuilder<[EchoPlugin]>) => {
  doc.echo.add('packageX', packageXEcho)

  doc.book('/packageX', 'Package X')
    .index(doc.markdown(packageXMd))
    .page('API', doc.markdown(packageXAPIMd))

  // plus anything else you feel like doing that is package-specific
}
```

Your main entry point should import all of these functions,
calling them sequentially, plus anything you would consider
"root level".

```ts
// docs/main.ts
import { createDocsPackageA } from '../packageA/docs';
import { createDocsPackageB } from '../packageB/docs';
import { createDocsPackageC } from '../packageC/docs';

const doc = new DocBuilder([EchoPlugin]);

// init individual package docs
createDocsPackageA(doc);
createDocsPackageB(doc);
createDocsPackageC(doc);

doc.landingPage('/', h(HomePage))

render(h(DocSite, { doc }), document.body);
```
