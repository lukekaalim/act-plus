# Static Generation

## What is Static Generation?

**Server Side Generation** (SSG) is the process of generating a "static"
website (HTML, CSS, JS and other files) that can be easily cached,
crawled by web bots from some kind of template or process. We'll call this
"Static Generation".

> **Server Side Rendering** (SSR) is a similar technique which
> just performs the generation at
> request time on the server. Since Grimoire is not really a server
> library, we're focusing on generating content statically at "build time" in
> this document, but the techniques are applicable if you want to perform
> server sider rendering.

Without any kind of generation, you're likely using Grimoire
as a **Single Page App** (SPA), a technique which
uses a single HTML/JS file to render out the application dynamically when
the client loads it. A downside of this technique is that its hard to
statically analyze the website, since the content requires the execution
of javascript.

However, if you've build a documentation website with the DocBuilder,
we can get the best of both worlds! Since you've described the site
to the DocBuilder, it can be generated at build time, but we can use
Act to rehydrate the HTML content into our application (making it behave
more like an SPA).

## Solution

The main way to perform static generation is create two "entry points",
one for the static generator and one for the client.  Both will import
code from the main source, but will "do something different":
  - In our static generator's case, it will be writing HTML to a filesystem.
  - In our client's case, it will be generating DOM elements in a browser
      (and rehydrating the components based on the HTML it finds on the page).

> We use NodeJS here, but theres little reason why you can't use
> a different JS/TS runtime.
>
> A more comprehensive integration might involve including this
> in your bundlers config or as a plugin - but we'll keep it basic
> in this guide.

You should be aware that your code will be executing potentially in
_two different_ runtimes, the build-time NodeJS and the run-time JS 
browser engine. Thus, at different points in the code, different rules
and environments apply.

For instance, if you generate a timestamp with `Date.now()`, then it
will either be the time the generator build the website and unchanging,
or it could be the time right now when the client executes the code.

>
> We're going to make a script with will generate some HTML,
> but its still up to you to bundle you application code so
> you can reference it: `<head> <script src="client.js">` etc.
